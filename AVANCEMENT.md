## 1. Décisions techniques

| Sujet | Choix | Raison |
|---|---|---|
| Framework | **Flutter** (Dart) | Un seul code pour Android, iOS et web ; rendu identique partout |
| Stockage local V1 | **shared_preferences** (liste des personnages en JSON) | Fonctionne partout (y compris le web), zéro configuration. À remplacer par Drift/SQLite si le volume grossit |
| Architecture | Écrans → `PersonnagesController` (ChangeNotifier) → `PersonnageRepository` (interface) | Permet d'ajouter le cloud en phase 2 sans toucher aux écrans |
| Gestion d'état | `ChangeNotifier` + `ListenableBuilder` (natif Flutter) | Pas de dépendance ; passer à Riverpod si l'app se complexifie |
| Navigation | Menu latéral (`NavigationDrawer`) + `Navigator` natif pour les détails | L'écran racine affiche la section choisie ; le bouton retour ramène à Personnages. go_router si besoin d'URL propres sur le web |
| Préférences | `PreferencesController` + shared_preferences (clé `odv.preferences.theme`) | Thème système / clair / sombre conservé d'un lancement à l'autre |
| Données de référence | JSON embarqués (`V1/assets/data/`) : races, classes, aptitudes, équipements, bestiaire ; règles en Markdown (`regles_systeme.md`) | Changent rarement, pas besoin du réseau. Pour ajouter une arme ou une créature : compléter le JSON |
| Règles de calcul | Toutes dans `lib/regles/fiche_calculee.dart` | Un seul fichier à modifier quand les règles évoluent |
| Sauvegarde en ligne (phase 2) | **Firebase** (Auth + Firestore) | Cache hors-ligne intégré, offre gratuite suffisante ; projet `odyssee-vagabonds` (02/11/2026) : e-mail + Google, sans compte = fiches sur l'appareil (envoyées à la création du compte), collection `personnages` avec `proprietaire` / `partageAvec` (prépare le jeu à plusieurs) ; Android et web seulement |
| Campagnes (phase 2) | Firestore : `campagnes/{id}` (MJ, `joueurs` / `demandes` en uids, code, paramètres, séance), `campagnes/{id}/prive/mj` (script, notes : MJ seul), `campagnes/{id}/membres/{uid}` (personnage, statut), `codes/{code}` → campagne ; `ServiceCampagnes` (Firestore / mémoire pour les tests), `CampagnesController` | Invitation fiable par code validé par le MJ ; le script reste privé ; fiches partagées par `partageAvec` (jamais effacé par une sauvegarde : écriture en fusion) ; avertissement de séance en temps réel dans l'app (03/11/2026) |
| Univers (anticipé) | Champ `univers` (id, `models/univers.dart`) sur `Personnage` (schéma 9), `Classe`, `Race`, `Voie` ; l'univers porte son groupe de statistiques (`Univers.caracs`) ; clé JSON facultative, absente = `medieval-fantastique` ; `Referentiel.racesDe` / `classesDe` ; champ `univers` aussi sur le document Firestore | Le système à d20 pourra servir à d'autres univers que le médiéval fantastique ; rien d'affiché tant qu'un seul univers existe (03/11/2026) |
| Langue | Interface en français (`flutter_localizations`) | — |
| Fichiers (import / export) | Paquet `file_picker` (^10) + secours copier-coller du texte | Fonctionne sur web, Android, iOS et ordinateur ; le copier-coller marche même si l'accès aux fichiers échoue |
| Lancement web (dev) | `flutter run -d web-server --web-port=8080` (via `lancer_web.bat`), toujours sur **http://localhost:8080** dans le même navigateur | Sur le web, la sauvegarde locale est liée au navigateur et à l'adresse : une adresse fixe la conserve d'un lancement à l'autre |

### 7.3 Compétences (règles appliquées)

- Points de compétence par niveau : 3, 2, 2, 2, 3, 2, 2, 2, 2, 4 (24 au niveau 10) ; **+1 au départ pour l'humain**.
- Coût des rangs d'une voie : 1, 1, 2, 2, 3 (voie complète = 9). Rangs pris **dans l'ordre**, **rang ≤ niveau**.
- Voie raciale : rangs **offerts** aux niveaux impairs (rang 1 dès la création).

- ✅ (19/10/2026) **Pas d'obligation de tout dépenser** : les points restants sont **conservés** pour les niveaux suivants (ils se recalculent : total reçu − dépensé).
- ✅ (19/10/2026) Les points peuvent aussi acheter des **aptitudes / connaissances à 1 point** : natation, équitation, maîtrise d'une arme, d'un instrument, nouvelle langue, connaissance d'un domaine, lire et écrire (inné si INT ≥ 10), autre (accord du MJ). Liste dans `assets/data/aptitudes.json`.
- ✅ (25/10/2026) **Savoirs et savoir-faire** : connaissance = **savoir**, aptitude = **savoir-faire / action**. Chaque entrée : +5 aux tests liés ; **complexe** → −5 sans la maîtrise, **basique** → pas de malus. Caractéristique indiquée par entrée ; **pas de SAG** dans ce système (remplacée par INT). Une connaissance **par peuple** (« Peuple nain »…), **innée pour sa propre race** (règle §5.5) ; un savoir-faire **par artisanat** (couture, menuiserie, joaillerie, travail du cuir, poterie, tissage ; DEX, complexes) — 25/10/2026.

### 7.8 Jets de dés du personnage (22/10/2026)

- Test de caractéristique = **1d20 + mod(stat)** (règles : « jet de test = d20 + bonus » ; §7.2 n° 14).
- Critiques (20 / 1 naturels) seulement sur les jets de d20 ; avantage / désavantage aussi.
- ❓ Effet d'une réussite critique sur les dégâts : non défini dans les règles, **rien n'est appliqué** (à trancher).
- Les bonus de tests situationnels (§7.6) ne sont pas ajoutés automatiquement : ils sont rappelés sous les boutons.

### 7.7 Équipement porté ✅ (22/10/2026)

Limites : 1 armure, 1 casque, 2 bijoux, **2 mains** : 1 arme / bouclier à une main **et** 1 arme / bouclier à une main, **ou** 1 arme / bouclier à deux mains. Arme à une ou deux mains (bâton) : 1 ou 2 mains selon la prise. Code : `ReglesInventaire` (`lib/regles/inventaire.dart`).
